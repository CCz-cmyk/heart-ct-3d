心脏CT 3D可视化系统 — 迁移到其他电脑 使用说明
==================================================

【一、在原电脑准备】
1. 双击 stop.bat，停止所有服务（必须做，否则数据库文件可能拷贝不完整）
2. 把整个 heart_3d_project 文件夹拷到 U 盘 / 移动硬盘
   （体积约 2.4 GB，数据库、病例数据、程序都已在文件夹里）
   也可以双击 pack_for_other_pc.bat 自动打包成桌面上的 heart3d_portable.zip

【二、在目标电脑】
1. 把文件夹放到任意位置（如 D:\heart_3d_project）
   路径尽量不含中文和空格，更稳妥
2. 安装 Python 3.11.9（必须）：
   https://www.python.org/ftp/python/3.11.9/python-3.11.9-amd64.exe
   安装时务必勾选 "Add python.exe to PATH"
3. 安装微软 VC++ 运行库（MySQL 和 Node 都需要，多数电脑已有）：
   https://aka.ms/vs/17/release/vc_redist.x64.exe
4. 双击 first_setup.bat（首次安装，只跑一次）
   作用：自动重建 Python 虚拟环境、安装后端依赖、检查前端依赖
   需要联网，约 2~5 分钟
5. 双击 start.bat 启动，浏览器会自动打开 http://localhost:5173
   登录账号 root    密码 root

【三、日常使用】
- 启动：双击 start.bat（或桌面快捷方式）
- 停止：双击 stop.bat
- 数据库里已有 10 个病例，不需要重新导入

【四、DICOM 影像数据（答辩演示用）】
1. 位置：data\dicom\case_01 … case_10，每例 192 个切片（IM0001.dcm … IM0192.dcm）
   整套约 240 MB，已包含在文件夹里，拷贝时不要漏掉 data 目录
2. 万一 data\dicom 丢了或为空：
   backend\venv\Scripts\python.exe backend\make_dicom.py
   （只做一例：加 --case 1；只做前两例：加 --limit 2）
   重新生成后 start.bat 照常启动即可，约 1~2 分钟
3. 页面上看：打开病例后，左侧「影像数据源」点「DICOM 序列」，
   3D 与三视图都由 .dcm 逐层解析重建（首次解析稍慢，之后走 data\dicom_cache 缓存）
4. 用外部查看器验证（答辩时最能证明"标准 DICOM"）：
   点「下载 DICOM 序列（zip）」→ 解压得到 192 个 .dcm → 用下列任一软件打开整个文件夹
   - RadiAnt Viewer（免费，Windows，把文件夹直接拖进去）
   - MicroDicom Viewer（免费，Windows）
   - 3D Slicer（免费，可做 MPR 与三维重建）
   导入时如询问，选择 Import / Open directory / Add folder，不要选单个文件
5. 导入别人的 DICOM：点「导入 DICOM（zip）」，上传 .zip（≤500 MB、≤1200 片），
   系统解包校验后立即三维渲染
6. 新建档案（上传 DICOM 即建档）：在「病例档案」列表页点「+ 新建档案」，
   填检查号、姓名、性别、年龄、检查日期、检查项目，选一个 DICOM 序列的 .zip，
   点「创建并解析」→ 系统解包、解析成体数据、写入数据库，列表里立刻多一条档案，
   点「3D 查看」即可用刚上传的 .dcm 出三维图（新档案没有预置病灶，AI 分析会显示「未检出」）
   注意：检查号不能与已有档案重复（如 P0001 已被占用）
7. 编辑 / 删除档案：列表每行有三个按钮「3D查看」「编辑」「删除」
   「编辑」可改检查号、姓名、性别、年龄、检查日期、检查项目（影像数据不变，检查号不能与他人重复）
   「删除」会弹二次确认，确认后该档案的病灶、体数据 .npy、DICOM 序列目录一起删掉，不可恢复
   （预置的 10 个病例删掉后，重跑 seed_data.py 与 make_dicom.py 可以恢复）
8. 3D 展示模式：左侧「3D 展示」组可切「解剖模型」/「体数据渲染」
   「解剖模型」：glb 三维心脏（心脏 + 冠脉 + 肺血管树），可拖动旋转、滚轮缩放，
      首次进页面会显示加载进度（约 73 MB）；该病例已入库的病灶会以黄色小球标在模型上
      病例专属模型：把该病例的模型按 case_01.glb、case_02.glb …… 命名，放进
      frontend\public\models\ 目录，进对应病例页面就自动用专属模型（视图右下角提示「本病例专属模型」）；
      没有对应文件时回退通用 heart_model.glb，提示「通用解剖模型（无专属文件时）」
   「体数据渲染」：按当前病例的 DICOM 体素重建，才支持窗宽窗位与体渲染裁剪
   模型模式下「窗宽/窗位」「体渲染裁剪范围」面板自动置灰，AI 分析不受影响
9. 下方三张图：默认是「三方相 3D 剖切」——把上面那颗 3D 模型沿轴位 / 冠状 / 矢状方向实时剖开，
   剖面位置跟左侧「MPR 切面位置」的轴位 Z / 冠状 Y / 矢状 X 滑块联动；
   点「2D 精读 / 测量」可切回标准 DICOM 切片三视图（灰阶，支持切面测距），再点回来即恢复模型剖切
   剖开后切面是实心的（暗红心肌 + 中心渐暗的心腔），不是空壳内壁；
   三格各可拖拽旋转、滚轮缩放，双击复位

【五、常见问题】
1. 启动报错或页面打不开
   先看三个黑窗口有没有报错；确认 3306 / 8000 / 5173 端口没被占用
   （目标电脑若装过 MySQL 服务，先停止它，否则 3306 冲突）
2. 提示缺少 VCRUNTIME140.dll
   装第 2 步的 VC++ 运行库
3. 杀毒软件拦截 mysqld.exe / node.exe
   选择"允许运行"
4. first_setup.bat 提示找不到 Python
   安装 Python 时没勾选 Add to PATH，重新安装勾选即可
5. 换了盘符或路径
   脚本都是相对路径，不需要改任何配置
6. 页面显示 DICOM 徽标但三维区域是黑的
   先点「NPY 体数据」确认基础渲染正常，再点回「DICOM 序列」；
   仍异常时查看后端黑窗口的报错信息
7. 三维区域一直显示「正在加载三维心脏模型」
   确认 frontend\public\models\heart_model.glb 还在（73.3 MB），丢了就从原电脑补回这个文件
   点「体数据渲染」可以先看由 DICOM 重建的三维图，不受模型文件影响
8. 目标电脑上「解剖模型」报找不到 glb / 页面白屏
   说明前端依赖或模型文件没随文件夹一起拷过来：确认 frontend\node_modules\three 存在，
   缺失时在 frontend 目录执行 npm install（或重跑 first_setup.bat）
